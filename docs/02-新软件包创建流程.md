# ComfyUI-Ollama-QWEnhancer 新软件包创建流程

> 版本：v0.1
> 配套文档：[`01-系统需求分析.md`](./01-系统需求分析.md)、[`03-功能对等矩阵.md`](./03-功能对等矩阵.md)
> 自动化脚手架：[`../tools/scaffold_package.sh`](../tools/scaffold_package.sh)

本流程定义从「零」到「可发布」的 8 个阶段（P0–P7）。每个阶段都给出 **输入 / 动作 / 产出 / 门控（Gate）/ 验证命令**，未通过门控不得进入下一阶段。

---

## 0. 流程总览

```
P0 前置校验 ──► P1 骨架与元数据 ──► P2 核心层 ──► P3 节点实现 ──► P4 Web UI ──► P5 集成冒烟 ──► P6 功能对等验收 ──► P7 打包发布
   G0              G1                  G2            G3             G4            G5               G6                G7
```

**原则**

1. **先契约后实现**：P2 先把 Ollama 客户端封装与数据类型定死，P3 只做参数映射。
2. **每阶段可回滚**：阶段产出物独立，任一 Gate 失败只回退当前阶段。
3. **门控即命令**：每个 Gate 都有一条可在终端直接执行的验证命令，不靠人工目测。
4. **上游只读**：`../comfyui-ollama`、`../ComfyUI-QwenVL` 全程只读参考，不做 git 子模块、不做运行期依赖。

### P3 · 节点实现

| 项 | 内容 |
| --- | --- |
| **输入** | P2 核心层 |
| **动作** | 按 §3 节点清单实现 5 个节点，只做「widget → 核心层调用 → 输出」的映射，不含业务逻辑 |
| **产出** | 5 个节点类 + 映射表 |
| **Gate** | **G3：ComfyUI 中 5 个节点可见且能连成工作流** |

```bash
# G3 验证（节点注册自检）
python3 -c "
import ast, pathlib
names=set()
for p in pathlib.Path('nodes').glob('*.py'):
    t=ast.parse(p.read_text(encoding='utf-8'))
    for n in ast.walk(t):
        if isinstance(n,ast.Assign) and getattr(n.targets[0],'id','')=='NODE_CLASS_MAPPINGS':
            names |= {k.value for k in n.value.keys}
print(sorted(names))
assert len(names)==5"
```

## 6. 部署（P7 的第 ④ 步）

本环境的 `/NVME`（ComfyUI 所在文件系统）当前为**只读挂载**：

```
$ findmnt -T <ComfyUI>/custom_nodes
TARGET SOURCE         FSTYPE OPTIONS
/NVME  /dev/nvme0n1p3 xfs    ro,nosuid,nodev,relatime,...
```

因此无法从工作区直接写入 `custom_nodes/`。用部署脚本先做体检：

```bash
bash tools/deploy_to_comfyui.sh            # 只检查并给出指引
bash tools/deploy_to_comfyui.sh --copy     # 目标可写时执行复制
bash tools/deploy_to_comfyui.sh --link     # 目标可写时建立符号链接
```

处理只读挂载（三选一）：

| 方案 | 命令 | 说明 |
| --- | --- | --- |
| 临时改读写 | `sudo mount -o remount,rw /NVME` | 最直接；重启后失效 |
| 挂载可写副本 | 把 ComfyUI 迁到可写盘 | 影响面大 |
| 手工复制 | 由有权限的用户 `cp -r` | 无需改挂载 |

部署后重启 ComfyUI，日志应出现：

```
[ComfyUI-Ollama-QWEnhancer] v0.1.0 | 4 nodes Loaded
[OllamaQWEnhancer] 已注册模型列表路由 POST /ollama_qwenhancer/list_models
```

## 7. 日常开发循环（推荐用法）

```bash
cd ComfyUI-Ollama-QWEnhancer

# 1) 改完代码先跑离线门控（秒级，不需要 Ollama）
QWE_OFFLINE=1 bash tests/run_all.sh

# 2) 再跑实网端到端（约 5 秒）
bash tests/run_all.sh

# 3) 只改 web/js 时无需重启 ComfyUI（前端热重载），
#    改 Python 需重启 ComfyUI 进程
```

**排查顺序建议**：G1 语法 → G2 离线 → G4 路由 → G5 冲突 → G6 实网。
绝大多数问题会在 G2/G5 阶段暴露，不必反复重启 ComfyUI。
