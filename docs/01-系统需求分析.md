# ComfyUI-Ollama-QWEnhancer 系统需求分析

> 版本：v0.1（分析稿）
> 需求来源：[`README.md`](../README.md)
> 上游代码基线：`../comfyui-ollama`（v2.1.0）、`../ComfyUI-QwenVL`（v2.3.2）
> 分析对象：拟新建包 `ComfyUI-Ollama-QWEnhancer`

---

## 1. 目标与范围

### 1.1 一句话目标

把 **ComfyUI-QwenVL 的推理侧能力**（VL 图像/视频理解 + Prompt 增强）移植到 **Ollama 推理后端**上，去掉所有本地模型加载、编译与下载逻辑，输出一个全新的独立 ComfyUI 自定义节点包。

### 1.2 范围内（In Scope）

| 编号 | 内容 |
| --- | --- |
| S1 | 新增包 `ComfyUI-Ollama-QWEnhancer`，可被 ComfyUI 以 custom_node 形式加载 |
| S2 | 通过 Ollama HTTP API 完成 VL 推理（图像/多帧视频）与纯文本推理 |
| S3 | 保留 QwenVL 的 Prompt 体系：预设 prompt、自定义 prompt、可选 system prompt、Prompt 增强风格 |
| S4 | 可选 Ollama 服务器地址（ip/port）、可查询并选择 Ollama 可用模型 |
| S5 | 复制/复用 QwenVL 的媒体预处理工具（tensor → PIL、帧采样、分辨率预算） |

### 1.3 范围外（Out of Scope）

| 编号 | 内容 | 理由 |
| --- | --- | --- |
| O1 | llama.cpp / GGUF 本地推理 | 由 Ollama 承担推理，GGUF 由 `ollama pull` 的模型 tag 表达 |
| O2 | 从 HuggingFace 下载模型 | README 明确要求删除 |
| O3 | 启动/管理 llama-server 子进程 | README 明确要求删除 |
| O4 | bitsandbytes 量化、SageAttention、FlashAttention、`torch.compile`、device 选择 | 属本地推理细节，Ollama 服务端自管 |
| O5 | `AILab_HuggingFaceDownloader` 节点 | 属下载功能 |
| O6 | NumBeam 束搜索 | Ollama API 无对应参数 |

## 2. 系统上下文

```
┌──────────────────────────── ComfyUI 进程 (Python 3.13 venv) ─────────────────────────────┐
│                                                                                          │
│  工作流 ──► ComfyUI-Ollama-QWEnhancer (本包)                                              │
│              ├── nodes/  (INPUT_TYPES / 参数映射)                                         │
│              ├── core/   (ollama 客户端封装、媒体适配、prompt 装载)                        │
│              ├── web/js/ (模型列表刷新按钮)                                                │
│              └── server route: POST /ollama_qwenhancer/list_models  ──┐                   │
│                                                                       │                   │
│  复用宿主能力: torch / numpy / PIL / aiohttp / comfy.utils.ProgressBar │                   │
│  类型检查期依赖: torch（仅 typing，运行期由 ComfyUI 提供）              │                   │
└───────────────────────────────────────────────────────────────────────┼──────────────────┘
                                                                        │ HTTP
                                                          ┌─────────────▼──────────────┐
                                                          │ Ollama Server :11434       │
                                                          │  /api/tags  /api/show      │
                                                          │  /api/generate  /api/chat  │
                                                          │  模型常驻由 keep_alive 控制 │
                                                          └────────────────────────────┘
```

### 2.1 关键结论：推理责任转移

| 关注点 | ComfyUI-QwenVL（旧） | ComfyUI-Ollama-QWEnhancer（新） |
| --- | --- | --- |
| 模型权重 | 本机 `models/LLM/Qwen-VL` | Ollama 服务端 |
| 模型加载/卸载 | 进程内 `from_pretrained` | Ollama `keep_alive` |
| 量化 | bitsandbytes 4/8bit 运行期量化 | Ollama 模型 tag（如 `qwen2.5vl:7b-q4_K_M`） |
| 注意力后端 | sage / flash_attention_2 / sdpa | 不适用 |
| 设备选择 | cuda:x / cpu / mps | 不适用 |
| 视频 | processor 原生 `videos=` 输入 | **降级为多帧多图**（见 FR-05、R1） |
| 生成参数 | `model.generate(**kwargs)` | Ollama `options` 字典 |

## 4. 功能需求（FR）

| ID | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| **FR-01** | 提供 Ollama 连接配置：`url`（默认 `http://127.0.0.1:11434`）、`model`、`keep_alive` + 单位 | 必须 | 节点可填任意 ip/port；产出连接对象供下游使用 |
| **FR-02** | 可查询 Ollama 可用模型并以下拉框选择；UI 提供刷新按钮 | 必须 | 点击刷新后下拉框出现服务器真实模型列表 |
| **FR-03** | **VL 模型识别**：通过 `/api/show` 的 `capabilities` 过滤出含 `vision` 的模型，VL 节点只列出多模态模型，文本增强节点列出全部 | 必须 | 无 vision 能力的模型不出现在 VL 节点；无模型时给出可读提示而不崩溃 |
| **FR-04** | 保留 QwenVL 的 Prompt 体系：9 条 `qwenvl` 预设 + `custom_prompt` 非空时**完全覆盖**预设 + 可选自定义 system prompt | 必须 | 与原实现语义一致（`AILab_QwenVL.py:832-834`） |
| **FR-05** | 图像输入：`IMAGE` 张量 → base64 PNG，长边上限 1280 | 必须 | 单图、批量图均可送出 |
| **FR-06** | 视频输入：按 `frame_count` 均匀采样，按 `video_frame_size`（`auto`/数值/`original`）做 token 预算降采样，**以多张 base64 图像数组**送 Ollama | 必须 | 与旧版预算算法一致；payload 不失控 |
| **FR-07** | 生成参数映射到 Ollama `options`：`max_tokens→num_predict`、`temperature→temperature`、`top_p→top_p`、`repetition_penalty→repeat_penalty`、`seed→seed`；`num_beams` 不对应，节点中移除 | 必须 | 参数在 `/api/generate` 或 `/api/chat` 请求体中生效 |
| **FR-08** | Prompt 增强节点：6 种 `qwen_text.styles` + 自定义 system prompt + 「增强风格 + 用户文本」拼接语义 | 必须 | 输出与原 `_invoke_text` 一致的形态 |
| **FR-09** | 输出契约：VL 节点返回 `("STRING",)` / `RESPONSE`；增强节点返回 `("STRING",)` / `ENHANCED_OUTPUT` | 必须 | 下游 Text 节点可直接连接 |
| **FR-10** | 进度反馈：模型请求阶段用 `comfy.utils.ProgressBar` 或等价机制上报 | 应该 | 长请求期间 UI 不假死 |
| **FR-11** | 连接与上下文复用：`keep_alive` 生效；可选把 Ollama `context` 透传以支持多轮 | 应该 | 连续两次运行第二次不重载模型 |
| **FR-12** | 调试开关：打印请求/响应摘要（对应上游 `debug` 选项） | 应该 | 默认关闭 |
| **FR-13** | 支持 `think`（思考型模型）并在 UI 上给出独立输出 | 可以 | 模型不支持时报错可读 |
| **FR-14** | 输出清洗：可剥离 `think` 块、代码围栏、角色前缀等，保证下游拿到纯净 prompt | 应该 | 移植 `clean_model_output`，对思考型模型输出有效 |

## 6. 非功能需求（NFR）

| ID | 类别 | 要求 |
| --- | --- | --- |
| NFR-01 | 依赖最小化 | 运行期仅需 `ollama`（Python 客户端）；`torch`、`numpy`、`PIL`、`aiohttp` 全部复用 ComfyUI 宿主，不写入 `requirements.txt` |

| NFR-10 | Payload 控制 | 单请求 base64 图像数量/尺寸有硬上限，超限降采样并告警 |

## 7. 接口契约

### 7.1 节点数据类型（建议新增，避免与上游撞名）

| 类型 | 结构 | 说明 |
| --- | --- | --- |
| `QWE_OLLAMA_CONN` | `{url: str, model: str, keep_alive: str}` | 连接 + 模型 + 常驻时长 |
| `QWE_OLLAMA_OPTS` | `{num_predict, temperature, top_p, repeat_penalty, seed, ...}` | 已展开的生成参数 |
| `QWE_OLLAMA_META` | `{conn, opts}` | 链式透传（对齐上游 `OLLAMA_META` 思路） |

> 决策点 D1：**自包含**（自有类型名，推荐）还是**复用**上游 `OLLAMA_CONNECTIVITY`（需强依赖 comfyui-ollama）。详见流程文档 §2.2。

### 7.2 HTTP 路由契约

| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| POST | `/ollama_qwenhancer/list_models` | `{"url": "http://..."}` | `{"models": [{"name": "...", "vision": true}], "error": null}` |

> **约束**：不得复用 `/ollama/get_models`。ComfyUI 的 `PromptServer` 基于 aiohttp，同一 path+method 重复注册会抛 `RuntimeError: Added route will never be executed`，导致后加载的包崩溃（R2）。

### 7.3 Ollama REST 契约

| 端点 | 用途 | 关键字段 |
| --- | --- | --- |
| `GET /api/tags` | 列出本地模型 | `models[].name` / `.model` |
| `POST /api/show` | 查模型能力 | `capabilities` 含 `"vision"` 时为多模态 |
| `POST /api/generate` | 单轮生成 | `model, system, prompt, images[], options{}, keep_alive, format, think` |
| `POST /api/chat` | 多轮生成 | `messages[{role, content, images[]}], options{}, keep_alive` |

图像以 **base64 字符串数组**放入 `images`；Ollama 无原生 video 字段（参考 [Ollama Vision 文档](https://docs.ollama.com/capabilities/vision)）。

## 10. 风险登记

| ID | 风险 | 等级 | 缓解 |
| --- | --- | --- | --- |
| R1 | 视频能力降级：Ollama 无原生 video，多帧无时序建模，运动/因果描述变弱 | 高 | 文档明示；提供 `frame_count` 上限与提示；对 `📹 Video Summary` 等预设追加“帧序”说明 |
| R2 | **命名/路由冲突**：与 `comfyui-ollama` 同装时 Node ID、数据类型、HTTP 路由重叠 | 高 | 独立前缀 + 独立路由；CI 增加冲突扫描（见流程 P5 Gate） |
| R3 | `ollama` 客户端版本差异导致 `think`/`format`/`keep_alive` 参数不被接受 | 中 | `requirements.txt` 固定 `ollama>=0.4,<1.0`；调用前做能力探测，失败降级重试 |
| R4 | 图像 payload 过大导致请求超时/OOM | 中 | 统一走 `max_side=1280`（图）/ 预算降采样（视频），并设帧数上限 |
| R5 | 与 `ComfyUI-QwenVL` 同装时 `system_prompts.json` 与预设名重复 | 低 | 本包使用独立文件名或独立 preset 命名空间 |
| R6 | GPL-3.0 传染性影响再分发方式 | 中 | 明确以 GPL-3.0 发布，保留上游版权头 |
| R7 | 无自动化测试，改动易回归 | 中 | 按流程 P5/P6 建立冒烟 + 对等性验收脚本 |
