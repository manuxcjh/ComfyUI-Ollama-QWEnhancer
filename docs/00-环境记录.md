## 1. Ollama 服务

| 项 | 实测值 |
| --- | --- |
| 地址 | `http://127.0.0.1:11434`（已设为包内默认值，可用 `QWE_OLLAMA_URL` 覆盖） |

| 模型总数 | **13** |
| 具备 vision 能力 | **6** |

### 1.1 模型清单

本包不维护模型清单，而是运行时从服务端查询：

```bash
curl -s http://<host>:11434/api/tags        # 列出全部模型
curl -s http://<host>:11434/api/show -d '{"model":"<name>"}'   # 查看单个模型能力
```

节点上的「🔄 刷新模型」按钮即调用本包的
`POST /ollama_qwenhancer/list_models`，对每个模型并发查询 `/api/show`
并用 `capabilities` 是否包含 `"vision"` 来过滤（FR-03）。

实测（本机局域网 Ollama，13 个模型）：其中 **6 个**具备 vision 能力，
纯文本模型会被 VL 节点正确拒绝。

### 1.2 主用模型能力（vision 模型的 capability 形态）

```json
POST /api/show {"model": "<vision-model>"}
→ capabilities: ["completion", "vision", "tools", "thinking"]
```

**⚠️ 模型名容错**：把模型名写错（例如多写一段 `-27B`）会得到
`model not found`。本包对此做了两层防护：

1. 下拉框默认值来自服务端查询结果（`core/types.py::DEFAULT_MODEL` 仅作离线兜底）
2. `resolve_model()` 容错解析：精确 → 忽略大小写 → 去 `:latest` →
   相似度 ≥0.85 且领先第二名 ≥0.05 时自动纠正并打印告警，否则报错并列出候选

### 1.3 关键发现：思考型模型的空响应陷阱

具备 `thinking` 能力的模型（如 Qwen3、DeepSeek-R1 系列）实测：

| 请求 | `response` | `thinking` | `done_reason` |
| --- | --- | --- | --- |
| 不传 `think` | **空** | 占满全部 token | `length` |
| `think=False` | ✅ 正常文本 | 空 | `stop` |
| `think=True` | 空（正文在 thinking 里） | 完整思考 | `length`/`stop` |

**结论**：必须**显式**发送 `think` 字段。已据此修改 `core/ollama_client.py::run()`，
并在正文为空且 `done_reason=length` 时打印增大 `max_tokens` 的提示。

另实测不具备 thinking 能力的模型：

| 请求 | 结果 |
| --- | --- |
| `think=False` | ✅ 正常返回 |
| `think=True` | ❌ 400 `"..." does not support thinking` |

因此 `run()` 对「模型不支持思考却要求 think」的情况会打印告警并以 `think=False` 重试。

## 4. 客户端 API 契约（0.6.0 实测）

| 方法 | 签名要点 |
| --- | --- |
| `Client(host=..., timeout=...)` | `timeout` 透传给 httpx，可用于 UI 快速探测 |
| `client.list()` | → `ListResponse`，`.models[].model`（**注意 `.name` 为 None**） |
| `client.show(model)` | → `ShowResponse`，`.capabilities: list[str]` |
| `client.generate(...)` | 支持 `system, prompt, images[], options{}, keep_alive, think, format` |
| `client.chat(...)` | `messages[{role, content, images[]}]`，`think` 可为 `low/medium/high` |

**类型陷阱**：响应是 pydantic 模型而非 dict，且 `list()` 的元素**只有 `.model`**。
`core/ollama_client.py::_field()` 已同时兼容属性与字典访问。

**路由类型陷阱**：`PromptServer.instance.routes` 是
`aiohttp.web.RouteTableDef`（`server.py:262`），**没有** `resources()` 方法
（那是 `UrlDispatcher` 的 API）。用 `resources()` 做重复检测会抛
`AttributeError`，导致路由永远注册不上。已改为迭代 `RouteDef.path`，
并加了 `tests/test_route_registration.py` 回归测试。
